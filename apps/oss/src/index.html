Deployment paths

Two deployment paths. One agent source.

Both paths start from the same .agent file. Pick the one that fits your team: a hosted API on Heroku, or the runtime embedded in an app you already operate.

01

Heroku self deploy

Declare your model and MCP servers inside the .agent file. Add the AgentScript buildpack and git push heroku main — no local build, no glue code. The packaged server provides REST, SSE, WebSocket, sessions, and optional Postgres.

02

SDK manual deploy

Compile AgentScript in your app, create a runtime agent with @agentscript/runtime-vercel, connect any AI SDK model, and expose it from Next.js, Hono, Express, workers, or your own job runner.

Architecture

What runs when an agent runs.

At execution time, AgentScript splits into three layers: the language you author, the runtime that executes it, and the adapters that connect it to a model and to your tools.

01

Agent language

A single .agent file declares behavior, tools, variables, and the deployment: block — model and MCP servers included.

02

Runtime

Loads the compiled IR, dispatches tool calls through ToolRegistry, maintains turn state, and emits a typed event stream for text, tool calls, and step boundaries.

03

Adapters

runtime-vercel drives Anthropic, OpenAI, Google, or any AI-SDK provider. Tool adapters like FnAdapter and McpAdapter wire local code or remote MCP servers into the same registry.

Packages

Use the whole server, or just the runtime pieces you need.

The packages map to the deployment choice. Heroku self deploy uses the server. Manual SDK deployment uses the runtime plus the Vercel AI SDK adapter. Advanced integrations can bring their own LLM driver directly to the runtime.

@agentscript/runtime v0.1

Agent execution core.

TypeScript runtime — no extra processes, no host-specific glue. Executes compiled AgentScript IR with ToolRegistry, turn state, guardrails, tracing, and checkpoints. You bring the host. 

import { Runtime, ToolRegistry, FnAdapter } from '@agentscript/runtime';

const fn = new FnAdapter();
fn.register('lookup_order', async ({ id }) => ({ status: 'shipped' }));

const tools = new ToolRegistry();
tools.register('fn', fn);

const runtime = new Runtime({ doc, tools, llm: myDriver });
const result = await runtime.turn('check ORD-42');
@agentscript/runtime-vercel v0.1

Manual SDK deployment path.

Vercel AI SDK adapter for Anthropic, OpenAI, Google, or any AI-SDK-compatible provider. Use it when your app owns routing, auth, persistence, and deployment. 

import { generateText } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { compileSource, createAgent } from '@agentscript/runtime-vercel';

const { output } = compileSource(source);
const agent = createAgent({
  doc: output,
  llm: { model: anthropic('claude-haiku-4-5'), generateText },
  tools,
});
const stream = agent.stream('check ORD-42');
@agentscript/cli v0.1

Bundle builder for non-Heroku targets.

Compile your .agent file(s) into the same bundle the Heroku buildpack produces, but locally — for Docker, Kubernetes, or any host that runs Node. Walks deployment: for env-var refs and emits a complete project layout. 

npx @agentscript/cli build agents/ \
  --out dist-agent --name my-agent

# dist-agent/
#   agents/*.agent
#   package.json
#   Procfile
#   .env.example
#   agentscript.json
@agentscript/server v0.1

Heroku-ready agent API server.

Hono-based server with REST, Server-Sent Events, and WebSocket sessions. Loads the LLM provider and MCP servers directly from the agent's deployment: block. In-memory or Postgres storage. 

# Bundle from `agentscript build` already wires this up.
AGENTS_DIR=./agents \
ANTHROPIC_API_KEY=sk-... \
node node_modules/@agentscript/server/dist/index.js

Heroku self deploy

One .agent file. One git push. Live agent.

The AgentScript Heroku buildpack turns a directory of .agent files into a running service. No package.json, no Procfile, no local build step. The buildpack runs the compiler on the dyno, scaffolds the server, and hands off to heroku/nodejs.

Write support.agent

The deployment: block declares the LLM and any MCP servers the agent needs. Use env(NAME) for secrets — they are resolved on the dyno at boot, never at compile time.

config:
    agent_name: "support"

deployment:
    llm:
        provider: "anthropic"
        model: "claude-haiku-4-5"
        api_key: "env(ANTHROPIC_API_KEY)"
    mcp:
        github:
            transport: "streamable-http"
            url: "https://mcp.github.com"
            auth:
                strategy: "api_key"
                key: "env(GITHUB_MCP_TOKEN)"

start_agent main:
    description: "Help customers check order status."
    reasoning:
        instructions: ->
            | Look up orders with mcp://github/lookup_order and reply.

Add the buildpacks

Order matters: the AgentScript buildpack runs first to scaffold package.json and Procfile, then heroku/nodejs installs @agentscript/server and boots the dyno.

heroku create my-agent
heroku buildpacks:add https://github.com/salesforce/agentscript-buildpack
heroku buildpacks:add heroku/nodejs

Set secrets and push

The buildpack lists every env(NAME) reference it found in .env.example. Set them with heroku config:set and deploy.

heroku config:set ANTHROPIC_API_KEY=sk-... \
                  GITHUB_MCP_TOKEN=ghp_...
heroku addons:create heroku-postgresql:essential-0   # optional

git init && git add . && git commit -m "init"
git push heroku main

Open a hosted session

Clients talk to the hosted agent over REST, SSE, or WebSocket.

BASE=https://my-agent.herokuapp.com

SID=$(curl -s -X POST $BASE/einstein/ai-agent/v1/agents/support/sessions \
  -H 'Content-Type: application/json' \
  -d '{"userId":"u1"}' | jq -r .sessionId)

curl -N -X POST $BASE/einstein/ai-agent/v1/sessions/$SID/messages \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{"message":"check ORD-42"}'

Targeting Docker, Kubernetes, or another platform? Use npx @agentscript/cli build agents/ --out dist-agent locally to produce the same bundle the buildpack would generate on Heroku, then ship it however you like.

SDK manual deploy

Embed AgentScript support in your own TypeScript app.

Use this path when you already have an API surface, auth model, or deployment target. The runtime executes the agent. The Vercel AI SDK provides the model. Your app decides how requests, sessions, and persistence work.

1. Compile the agent and wire its tools

import { generateText } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { ToolRegistry, FnAdapter } from '@agentscript/runtime';
import { compileSource, createAgent } from '@agentscript/runtime-vercel';

const { output } = compileSource(agentScriptSource);

const fn = new FnAdapter();
fn.register('lookup_order', async ({ order_number }) => ({
  status: order_number === 'ORD-42' ? 'shipped' : 'unknown',
}));

const tools = new ToolRegistry();
tools.register('fn', fn);

export const agent = createAgent({
  doc: output,
  llm: { model: anthropic('claude-haiku-4-5'), generateText },
  tools,
});

2. Stream it from your own HTTP route

export async function POST(request: Request) {
  const { message } = await request.json();
  const stream = agent.stream(message);
  const encoder = new TextEncoder();

  const body = new ReadableStream({
    async start(controller) {
      for await (const chunk of stream.textStream) {
        controller.enqueue(encoder.encode(chunk));
      }
      controller.close();
    },
  });

  return new Response(body, {
    headers: { 'Content-Type': 'text/plain; charset=utf-8' },
  });
}

The SDK path is intentionally small: compile the agent, register tools, connect an AI SDK model, then stream from your own route. It works anywhere TypeScript and the Vercel AI SDK work.
